# 多模型模拟测试记录（2026-10-23，Harbor 环境实跑）

目的：检验工具对“没见过的代码”是否仍然可靠，并对比两个模型在同一套提示规则下的产出。
口径先说清：本文件全部是 **AI 生成的模拟数据**，只作功能测试证据使用，不是真实学生提交、更不是用户试用反馈。OpenRouter 按用户决定跳过，第二个模型用已登录的 Claude（Claude Code CLI）。

## 实验一：Claude 盲写模拟提交，工具独立判定

方法：每道题单独调用一次 Claude，只给题面、不给参考解和已有代码，要求它扮演两位不同水平的学生各写一份提交，并以批改者身份预测每份对错。共 3 道题、6 份提交。随后由 Harbor 逐份人工读代码定真实对错，再用工具（人工模板策略 + 差分测试 3 轮）独立判定，三方对照。

| 提交 | Claude 预测 | 人工核对 | 工具判定 | 工具给出的最小反例 |
| --- | --- | --- | --- | --- |
| p001 提交一（排序去重取第二） | 正确 | 正确 | 正确 | — |
| p001 提交二（用 -1 做哨兵初值） | 错误 | 错误 | 错误 | [0,-1]，期望 -1、实际 None |
| p002 提交一（遍历累加正数） | 正确 | 正确 | 正确 | — |
| p002 提交二（先用 max 判断再累加） | 错误 | 错误 | 错误 | []，期望 0、实际报错（空列表调用 max） |
| p003 提交一（len(set)） | 正确 | 正确 | 正确 | — |
| p003 提交二（排序后数相邻不同） | 错误 | 错误 | 错误 | []，期望 0、实际 1 |

结论：工具对 6 份没见过的提交判定与人工核对 **6/6 一致**，三类错误（哨兵初值、空输入未处理、计数初值差一）都被抓到并给出可复现的最小反例。Claude 对自己两份提交的预测也 6/6 与人工一致——这是模型自评的一个个案数据，不构成对学生水平的任何结论。

原始生成输出存于 `模拟测试/claude_raw/`，抽取后的代码存于项目 `sim_submissions/`，判定明细存于 `模拟测试/判定结果.json`。

## 实验二：同一反例、同一提示规则，Claude 与 DeepSeek 对比

方法：把 p001 两道已知错解和已验证反例按项目原提示词规则（看不到参考解、每层不超过 60 字、只输出三层提示）交给 Claude 生成提示，再用项目自带的泄题检查核验，并与此前 DeepSeek（按 API 返回记为 deepseek-flash）的产出逐条对照。

- 泄题检查：Claude 两组提示均通过；DeepSeek 在这两组上也均通过（此前在 p003 上曾被拦截过一次，见扩题验证记录）。
- bug_init_zero：两家都准确点到“用 0 初始化”的病因。Claude 的 L3 多解释了一句“0 不是列表里的值”；DeepSeek 的 L1 把出错条件概括为“所有不同值都小于等于 0”，不够准确（例如 [5,-1] 也会出错）。
- bug_no_dedup：Claude 的 L3 同时指出长度检查数的是元素个数、不是不同值个数，病因比 DeepSeek 版更完整；DeepSeek 版整体更短。

结论（个案级，样本只有 2 组）：两个模型在本规则下都能产出不泄题、指得到病因的三层提示，Claude 版解释更细、DeepSeek 版更简洁。不据此宣称任一模型整体更强；正式评测应扩到全部题目并用统一量表逐项打分。

Claude 版提示全文存于 `模拟测试/claude提示.json`，DeepSeek 版见 `真实LLM首验记录.md`。
